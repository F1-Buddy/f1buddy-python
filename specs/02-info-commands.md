## `/schedule`

**Purpose.** Show the next race weekend: sessions, local times, countdown, circuit, weather.

**Parameters.** None.

**Data.**
- `series.f1.season_schedule(year)` → `list[Event]`, built from the FastF1 schedule (testing excluded).
- Circuit coordinates from Jolpica `races(year)`; weather from `weather.py`.

```python
@dataclass(frozen=True)
class SessionSlot:
    name: str              # as FastF1 names it: "Practice 1", "Sprint Qualifying", "Race"
    start_utc: datetime

@dataclass(frozen=True)
class Event:
    series: str
    year: int
    round: int
    name: str              # "Singapore Grand Prix"
    country: str
    location: str
    sessions: list[SessionSlot]   # chronological
```

**Behaviour.**
- The next event is the first one whose final session starts less than 3 hours ago or in the future. This keeps the current weekend showing during the race.
- If the current year has no such event, use the first event of next year's schedule when FastF1 has it; otherwise the off-season embed.
- Session emoji is chosen by session name, not by position: Practice 1/2/3 → `:one:` `:two:` `:three:`; any name containing "Qualifying" or "Shootout" → `:stopwatch:`; "Sprint" → `:race_car:`; "Race" → `:checkered_flag:`. This is correct for every sprint format.

**Output.**
- Title: `Race Schedule for {flag} **{name with "Grand Prix" shortened to "GP"}** {flag}`. No flag if the country is unknown.
- Description: `Race is <t:{race}:R>!`
- Two inline fields: "Session" (emoji + name per line) and "Time" (`<t:{start}:f>` per line, shown in each viewer's local time).
- Image: circuit outline PNG (see below), omitted if unavailable.
- Weather, when the race starts within 72 hours and the forecast was fetched: fields "Day" (actual weekday name of each event day), "Temperature" (`{min}–{max} °C`), "Precipitation" (`{mm} mm ({probability}%)`). Otherwise footer "Weather forecast available within 72 hours of race".
- Off-season embed: title "Race Schedule", description "It is currently off season! :crying_cat_face:", one of the existing GIFs at random, footer "Schedule will be available 2 weeks before the first GP".

**Circuit image.** `render/plots/circuit.py` draws the outline from the position data of the fastest qualifying lap at the same circuit in the most recent earlier season, white line on the standard black background, with the watermark. The PNG is cached forever per circuit. It is generated by the weekend task (spec 05) or `warm_cache.py`, never inside the command: if no cached image exists, the command sends without one.

**Errors.** Weather or image failure → that section is omitted. Schedule failure → `SourceError`.

**AC.**
1. With the clock set mid-season, the embed shows the next event with one row per session, in order.
2. With the clock set 1 hour after a race start, that race's event is still shown; 4 hours after, the following event is.
3. Each sprint-format fixture (2021, 2023, 2024) produces the emoji mapping above.
4. Times are rendered as Discord timestamps from the UTC session times.
5. Weather raising `SourceError` yields a complete embed with the "available within 72 hours" footer.
6. Weather day labels match the weekdays of the event dates, regardless of today's date.
7. After the final race with no next-year schedule, the off-season embed is returned; with a next-year schedule, its round 1 is.

## `/wdc`

**Purpose.** Driver championship standings.

**Parameters.** `year` (optional, 1950+).

**Data.** `jolpica.driver_standings(year)`.

**Output.** Title "{year} Driver Standings". Inline fields "Position", "Driver", "Points".
- Driver cell: team emoji + name. The team is the driver's most recent constructor that season.
- Name shortening by number of drivers, to stay under the field limit: ≤22 full name; 23–24 initial + surname; 25–26 surname; more than 26 plain surname with no emoji.
- Points shown without a trailing `.0`.
- `:crown:` after the champion when the season is complete (final round has been run), including the current year.

**AC.**
1. A 20-driver fixture yields three fields with 20 lines each and full names.
2. A 30-driver fixture (1950s season) uses the shortest form and no field exceeds 1024 characters.
3. The crown appears for a completed season and not for one in progress.
4. `year=1949` and `year={next year}` each raise `UserError` naming the valid range.
5. A driver who changed team mid-season shows the later team's emoji.

## `/wcc`

**Purpose.** Constructor championship standings.

**Parameters.** `year` (optional, 1958+; the constructors' title did not exist earlier).

**Data.** `jolpica.constructor_standings(year)`.

**Output.** Title "{year} Constructor Standings". Fields "Position", "Team" (emoji + name), "Points". `:crown:` on the winner of a completed season. A constructor whose standings position is missing or non-numeric (McLaren in 2007) shows "EX", taken from the data, not from a hardcoded index.

**AC.**
1. The 2007 fixture shows "EX" for McLaren and correct positions for the others.
2. `year=1957` raises `UserError` naming 1958 as the first season.
3. Crown rule as for `/wdc`.

## `/constructors`

**Purpose.** List a season's constructors with nationality and titles won.

**Parameters.** `year` (optional, 1950+).

**Data.** `jolpica.constructors(year)`, `jolpica.constructor_titles()`.

**Output.** Title "{year} Constructor Information". Fields:
- "Team": emoji (when the season has 11 or fewer teams) + name linked to its Wikipedia URL.
- "Nationality": flag + nationality.
- "Championships": titles won to date, computed from standings; "0" if none.

**AC.**
1. A current-season fixture lists every team with a link, a flag and a title count.
2. Title counts equal the number of seasons in the fixture where that constructor finished first.
3. A nationality missing from `nationalities.json` renders without a flag and without an error.
4. A season with no constructors raises `UserError` "No constructor data for {year}".

## `/driver`

**Purpose.** Career summary for any driver in F1 history.

**Parameters.** `driver` (required). Autocomplete searches `jolpica.all_drivers()` by name, most recent drivers first, and returns the Jolpica driver id. Free text is matched against full name, surname and code, ignoring case and accents.

**Data.** `jolpica.driver_career(id)`, `wikipedia.photo(url)`.

**Output.**
- Title: full name, linked to the Wikipedia page. Thumbnail: nationality flag. Image: photo, if found.
- Description, one line each with the existing emojis: Seasons Completed, Championships, Entries, Starts, Poles, Wins, Podiums, Fastest Laps, Points.

**Behaviour.**
- Free text matching more than one driver (for example "Schumacher") → `UserError` listing up to 5 matches by full name.
- No match → `UserError` `Driver "{text}" not found. Try the full name.`
- Easter eggs: input containing "anurag", or equal to "saul", returns the existing joke embeds before any lookup.

**AC.**
1. Fixture career data for a multiple champion yields the correct count for every line, including championships ≥ 10 handled as a number.
2. "hamilton", "HAM", "Lewis Hamilton" and "lewis hamilton" resolve to the same driver; "perez" matches "Pérez".
3. An ambiguous surname raises `UserError` listing the candidates.
4. A photo lookup failure still returns the embed, without an image.
5. Autocomplete for "ver" returns Verstappen entries with current drivers first, at most 25 results.

## `/results`

**Purpose.** Race classification.

**Parameters.** `round` (optional), `year` (optional, 1950+).

**Data.** FastF1 session results for the Race session, loaded without laps or telemetry (FastF1 serves pre-2018 seasons from Jolpica itself).

**Output.** Title "{year} {EventName} Race Results". Fields "Position" (🥇🥈🥉 for the podium, the classified position or status code such as "DNF" otherwise), "Driver" (team emoji + full name), "Points". No highlights link.

**AC.**
1. A fixture race yields one line per classified entry in finishing order with medals on the first three.
2. Retired and disqualified drivers show their status, not a number.
3. No arguments returns the most recently completed race, including the final round of a finished season.
4. A future round raises `UserError` "That race hasn't happened yet."
5. In pre-season with no race run this year, no arguments returns last season's final race.
6. An unknown round name raises `UserError` `Round "{text}" not found for {year}.`

## `/qualifying`

**Purpose.** Qualifying classification.

**Parameters.** `round` (optional), `year` (optional, 1994+; earlier qualifying data is not available).

**Data.** FastF1 Qualifying session results.

**Output.** Title "{year} {EventName} Qualifying Results". Fields "Position", "Driver" (team emoji + full name), "Time": the driver's best time in the last segment they took part in, prefixed with it (`Q3: 1:29.158`); "No time" if none.

**AC.**
1. A fixture session shows Q3 times for the top ten, Q2 for the next five and Q1 for the rest.
2. A driver with no time set shows "No time".
3. Default round is the most recently completed qualifying session, which during a race weekend may be a later round than the latest race.
4. A sprint-weekend fixture returns the Grand Prix qualifying, not the sprint qualifying.

## `/fl`

**Purpose.** Fastest race lap, for one round or every round of a season.

**Parameters.** `round` (optional), `year` (optional, 2018+).

**Data.** FastF1 race laps → fastest lap. Each completed round's result is stored in the `cache` table with no expiry (key `fl:{year}:{round}`), so a season view only loads rounds it hasn't seen.

**Output.**
- Title "Fastest Lap {year}". Fields "GP" (flag + team emoji + driver code), "Laptime" (`M:SS.mmm`), "Tyre" (compound emoji + age in laps).
- More than 10 rows → a second embed "Fastest Lap {year} Continued", both in one message.
- 2018 uses the 2018 compound emoji set.
- A round whose data fails to load is listed as "{GP} — unavailable" and the others are still shown.

**AC.**
1. One round returns one row with driver, time and tyre from the fixture.
2. A full-season request with 24 cached rounds makes no FastF1 load and returns two embeds (10 + 14 rows).
3. The final round of a completed season is included.
4. One failing round produces an "unavailable" row and a successful reply.
5. `year=2017` raises `UserError` naming 2018 as the first supported season.
6. A round after the latest completed one raises `UserError`.

## `/help`

**Purpose.** List commands, or explain one.

**Parameters.** `command` (optional; autocomplete from the registered command list).

**Behaviour.** Text is generated from the command tree, so it cannot go out of date: each command's description and each parameter's name, description, whether it is required, and choices.

**Output.**
- No argument: title "f1buddy Help"; one line per command (`/name` — description), grouped as Information, Plots, FIA documents, Reminders, Predictions, Live; then the support-server and issue-tracker links.
- With a command: title "f1buddy Help - {name}"; description, parameter list, and the screenshot `assets/help/{name}.png` when one exists.
- Unknown name: "Command '{x}' not recognized. Use /help to see all commands." with the existing GIF.

**AC.**
1. Every registered slash command appears in the overview exactly once.
2. A test fails if a registered command or parameter has an empty description.
3. The detail view lists a command's parameters in declared order with required/optional marked.
4. A missing screenshot yields an embed with no image and no error.

## `/lightsout`

**Purpose.** Reaction-time game.

**Parameters.** None.

**Behaviour.**
1. Send embed "Lights out!" with a 2×5 grid of black circles; add a 🏎️ reaction.
2. Each second for 5 seconds, turn one more column red.
3. Wait a random 0.00–5.99 seconds (as today), then turn the grid black with the existing green-square and dash line.
4. The first 🏎️ reaction on **this message** by a **non-bot** user added **after** the lights went out wins.
5. Winner: title "And away we go!", description "{mention} got away the fastest!" + checkered flag, footer "Lights held for {delay} seconds · reacted in {t} s".
6. A user who reacted before the lights went out is a jump start: they are ignored for the win, and named in a "Jump start: {mentions}" line.
7. No valid reaction within 30 seconds: title "No one got away", and the game ends.

**AC.**
1. A reaction on another message, or by a bot, does not end the game.
2. A reaction before lights-out is reported as a jump start and a later valid reaction wins.
3. With no reaction, the handler returns after the timeout with the "No one got away" embed.
4. The delay and timeout are injected, so the test runs in milliseconds.

*Manual:* reactions and message edits against a real server.

## `f1$sync` (prefix command)

**Purpose.** Publish slash commands to Discord. Admin only.

**Behaviour.**
- Caller in `ADMIN_USER_IDS`: set presence to Listening "V10s | /help | {N} servers", sync the global command tree, reply "{mention} synced {N} commands".
- Otherwise: "{name} is not a bot admin! Can't sync :(".
- The bot's username is not edited (the old edit was rate-limited and could block the sync).
- This is the only prefix command, and the only reason the `message_content` intent is requested. The `members` intent is dropped.

**AC.**
1. A non-admin caller gets the refusal and `tree.sync` is not called.
2. An admin caller triggers exactly one sync and a reply with the returned command count.

*Manual:* run once against the real application.
